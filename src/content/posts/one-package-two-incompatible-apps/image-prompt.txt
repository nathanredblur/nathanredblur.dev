Article: How a single reusable developer tool is made to run inside two applications that share almost none of their stack. Instead of the tool reaching into each app for its router and its data cache, the tool exposes empty sockets and each application plugs in its own connections. The piece is about inverting the dependency at the boundary: the app hands the tool plain functions describing how things work here, so one package serves two incompatible hosts without forking.
Key elements: one central tool component with a small set of labeled empty sockets or ports on its edge; two different applications on either side, each with its own distinct router piece and cache piece; matching cables running from each app into the tool's sockets; one socket left unplugged on one side to show an optional connection; a clear line or membrane around the tool marking what it refuses to import.
